# Legacy backlog and the lightweight successor

The lightweight plugin at <https://github.com/gustavonline/openpaperdesign> is the product direction; this repository's Rust and standalone-desktop track is stopped ([successor issue #4](https://github.com/gustavonline/openpaperdesign/issues/4)). This note triages all 33 open legacy issues once. It closes nothing and changes no issue.

**Evidence level.** "Source-supported" means the named successor file contains the behaviour or instruction. It is *not* native acceptance: nothing here was run in Codex or Claude Code, and none of it is release-qualified. Successor paths are relative to the successor repository at commit `20860b0` (clean tree, plugin `0.7.0-preview.12`), read-only. Its commits `5df2db3`, `60b515c`, `0489e6f` and `20860b0` touch the Codex tools-menu entry, nested text editing, Notion sync state and Home previews. They are source-only until the owner accepts them natively, and their issues (#5, #6, #1, #2) remain open. Legacy rows below cite them only as pointers.

**Outcomes.** *Source-supported*: the legacy outcome is met in successor source. *Superseded*: standalone, Rust-only or process work the plugin direction retires. *Gap*: useful and unresolved, kept under the named open successor issue. Successor #1 is Notion save/open and sync experience, #2 Home thumbnails and Trash/Undo, #3 CI and the public release workflow, #4 this product-page and legacy cleanup (the catch-all for gaps with no exact match), #5 the browser More tools entry, #6 inline canvas text editing.

**Not claimed.** No row means "implemented" wholesale and none means automatic migration. Papers saved by the legacy app use a different format from the successor's `paper.json` (`skills/paper/references/paper-format.md`, `format:'openpaperdesign'`). They are preserved, never deleted or converted automatically, and any import path is qualified separately under #4.
